# レベニューコントロールシステム (MVP・初期フェーズ向け)

専任のレベニューマネージャーを配置できない小〜中規模宿泊施設（民泊、小規模ホテル）向けの、SaaS型レベニューマネジメント（収益最大化）システムです。

## 現在搭載されている機能とモックの違い

### ✅ 実装済みの機能（裏側で実際に計算・動作しているもの）
- **カスタムルールの作成と自動反映**: クライアント自身が「稼働率〇%以上で〇倍」というルールのしきい値や倍率を自由に設定・追加・削除でき、即時にダッシュボードに反映されます。
- **イベント倍率のカスタマイズ**: 週末や特定イベント時に加算する倍率（例：1.2倍）を施設ごとに設定・計算可能です。
- **プラン別機能分岐**: Standard, Pro, Enterpriseプランに応じた計算方法の変更。
- **安全装置（リミッター）の制御**: 算出された最終価格が必ず「上限価格」「下限価格」の範囲内に収まる制御。
- **オーバーブッキング防止（上限室数）**: 「総客室数」ではなく設定した「販売上限室数（ブロック数）」をベースにした安全な稼働率計算。
- **AI（機械学習）による価格予測モデル**: `scikit-learn` (ランダムフォレスト) を用いた価格予測機能（現在は起動時に生成したダミーデータを学習）。

### ⚠️ モック機能（デモ用の見せかけであり、実データと通信していないもの）
これらは商談後、クライアントの環境に合わせて本番開発（外部API連携等）を行います。
- **OTA・サイトコントローラーへの自動同期**: ステータスは表示されますが、実際の通信は行っていません。
- **稼働率データ・過去実績の取得**: カレンダーの日付からランダムにダミーの稼働率や収益データを生成して表示しています。
- **CSVアップロード機能**: UIのみで、実際のファイル読み込みとAIへの学習連携は未実装です。
- **PDCAサジェスト・カレンダー**: デモ映えするように用意した固定のダミーテキストやデータを使用しています。
- **ゲスト向けUIウィジェット**: 実際の自社サイトに埋め込むためのコード出力機能などは未実装です（デザインのみ）。

## 本番環境に向けたインフラ・セキュリティ設計方針
初期コストと保守運用コスト（経費）を極限まで抑えつつ、クライアント側にシステム管理の負担をかけないよう、以下の構成を採用予定です。
- **インフラ/DB**: Supabase等のBaaS（Backend as a Service）を活用。自動バックアップやマネージドなセキュリティパッチ適用により、低コストで高い安全性を確保。
- **APIキー管理**: 平文での保存を避け、Vault機能やサーバー環境変数による高度な暗号化（AES-256等）で保護。
- **通信**: 全経路（クライアントPC⇔本システム⇔各OTA/サイトコントローラー）でのSSL/TLS通信（HTTPS）の強制。

## 起動方法（ワンクリック起動）

面倒なコマンド入力を省くため、一括起動スクリプトを用意しました。

### Mac / Linux の場合
ターミナルを開き、以下のコマンドを実行するだけです：
\`\`\`bash
./start.sh
\`\`\`

### Windows の場合
エクスプローラーから \`start.bat\` をダブルクリックするか、コマンドプロンプトで以下を実行してください：
\`\`\`cmd
start.bat
\`\`\`

起動後、自動的にバックグラウンドでサーバーが立ち上がります。
- 👉 **ダッシュボード**: http://localhost:3000
- 👉 **API ドキュメント**: http://localhost:8000/docs
