# レベナビ 運用ルール

更新日：2026年8月29日

## 1. 問い合わせ受付

- 受付先は、公開画面の「お問い合わせ」に表示するメールアドレスへ統一します。
- 受付時に「施設名・登録メール・困っている画面・発生日時」を確認します。
- ログイン不能、決済、データ取得停止は優先して確認します。
- 顧客のパスワード、カード番号、APIキーは受け取りません。

## 2. 障害時の対応

1. Cloud Runの `/health` と `/ready` を確認します。
2. 運営管理画面で「7日間の失敗」と「最終成功」を確認します。
3. 取得障害の場合はApify実行履歴、画面障害の場合はCloud Runログを確認します。
4. 複数顧客に影響する場合は、判明した事実・暫定対応・次回連絡予定をメールで案内します。
5. 復旧後は原因、影響期間、再発防止策を記録します。

## 3. 振込顧客の利用開始

1. 通帳または銀行画面で着金を確認します。
2. 運営管理の「振込入金を記録」へ請求月、入金日、金額、利用期限を入力します。
3. 顧客一覧で同じ顧客の利用期限を確認し、「利用開始」を押します。
4. 月初に入金台帳と利用中の顧客一覧を照合します。
5. 未入金または解約時は「停止」を押します。

## 4. 解約受付

- 登録メールからの依頼で本人確認します。
- カード契約はStripeの契約管理画面、振込契約は運営管理画面で停止します。
- 停止日、最終利用日、データ取扱いを返信します。
- 即時返金など通常と異なる対応は、責任者の承認を記録します。

## 5. 月次確認

- 入金台帳と契約状態が一致しているか
- 取得成功数、失敗数、Apify利用量
- Stripeの売上・返金・支払失敗
- Supabase、Cloud Run、Apifyの請求額
- 問い合わせ件数と未対応案件

## 6. 権限管理

- 運営管理を使えるメールアドレスは `OPERATOR_EMAILS` で限定します。
- 退職・担当変更時は、Google Cloud、Supabase、Stripe、Apify、Resendの権限を同日に見直します。
- 共通パスワードは使わず、各サービスのメンバー招待と二段階認証を利用します。
