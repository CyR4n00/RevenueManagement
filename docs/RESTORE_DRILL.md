# Supabase データ復旧確認手順

本番データを壊さないため、復旧テストは別プロジェクトまたはSupabaseの復旧機能で作成した一時環境で行います。

## 事前確認

1. 対象プロジェクトとバックアップ日時を記録します。
2. 復旧先が本番ではないことを二人で確認します。
3. 顧客へ影響する本番接続文字列は変更しません。

## 確認項目

1. 組織、施設、比較施設、価格履歴、契約、入金台帳の件数を本番側で記録します。
2. 選んだバックアップから一時環境へ復旧します。
3. 上記テーブルが開け、件数と代表レコードが一致することを確認します。
4. RLSが有効で、匿名キーだけでは顧客データと入金台帳を読めないことを確認します。
5. テスト用のアプリからログインし、自分の組織だけが表示されることを確認します。
6. 実施日、復旧に要した時間、差異、担当者を運営記録へ残します。

## 注意

- バックアップの実際の復元操作は、Supabaseの契約プランと利用可能な復旧方式を確認してから行います。
- 本番データベースへ上書き復元しません。
- 接続文字列やパスワードをチャット、画面録画、手順書へ貼りません。
