# レベナビ 運営マニュアル

## 1. この文書の目的

本書は、レベナビの申込受付、契約反映、問い合わせ対応、データ取得監視、障害対応を行う運営担当者向けの手順書です。

秘密鍵、パスワード、接続文字列は本書やチャットへ記載しません。Google Secret Managerまたは各サービスの安全な管理画面で扱います。

## 2. 本番サービス

- アプリ：Google Cloud Run
- ログイン：Supabase Auth
- 業務データ：Supabase PostgreSQL
- カード決済：Stripe
- 競合価格取得：Apify
- 通知メール：Resend（送信ドメインの認証後に有効化）

公開URL：<https://revenavi-q4kqzv4efq-an.a.run.app/>

## 3. 運営アカウントの原則

- 個人間でパスワードを共有しない。
- Google Cloud、Supabase、Stripe、Apifyは、各担当者をメンバーとして招待する。
- 可能なサービスでは二段階認証を有効にする。
- 退職・担当変更時は、その担当者だけを削除する。
- 秘密鍵をメール、チャット、議事録、GitHubへ貼らない。

## 4. 新規顧客の受付

最初に次の情報を確認します。

- 施設名
- 担当者名
- ログインに使用するメールアドレス
- 支払方法（カードまたは銀行振込）
- 比較したい予約サイトと施設数
- 利用プラン

顧客には、先にレベナビでメールアドレスを登録してもらいます。契約情報は登録したメールアドレスにひもづきます。

## 5. カード払いの契約

1. 顧客がログインする。
2. 「月額プランを開始する」を押す。
3. Stripeの画面で支払情報を入力する。
4. Stripeから届く決済完了通知をレベナビが受け取る。
5. 契約状態が「利用中」へ変わる。
6. 顧客が施設の初期設定を行う。

契約状態が変わらない場合は、次を順番に確認します。

1. Stripeのテスト環境と本番環境を取り違えていないか。
2. Stripe上で支払いが成功しているか。
3. Webhookの送信結果が成功になっているか。
4. Cloud Runのログに `/webhooks/stripe` のエラーがないか。
5. Supabaseの `subscriptions` に対象組織の行があるか。

### カード払いの領収書・請求書

顧客には、レベナビの「設定」から「契約を管理」を押し、Stripeの「請求履歴」で必要な月の領収書または請求書を保存してもらいます。

書類が見つからないという問い合わせがあった場合は、Stripeで対象顧客、支払日、支払状態を確認します。顧客名、金額、対象月を照合してから案内し、別の顧客の書類を送らないでください。

## 6. 銀行振込の契約

銀行振込でも利用権を反映できます。許可された運営アカウントでログインすると、左側に「運営管理」が表示されます。

### 受付手順

1. 顧客にレベナビのアカウントを作成してもらう。
2. 登録したメールアドレスを確認する。
3. 振込先、金額、支払期限を案内する。
4. 入金を通帳または銀行画面で確認する。
5. 「運営管理」を開き、「振込入金を記録」へ顧客、請求月、入金日、金額、利用期限を入力する。
6. 顧客一覧で対象顧客の利用期限を確認し、「利用開始」を押す。
7. 顧客に再ログインしてもらう。

### 注意

- 入金を確認する前に利用中へ変更しない。
- メールアドレスだけで判断せず、施設名と担当者名も照合する。
- StripeのID欄へ架空の値を入れない。銀行振込では空欄にする。
- 契約期限を必ず記録する。
- 返金、未入金、解約時は、契約状態を停止へ変更する。

入金履歴は運営管理画面下部の「最近の入金台帳」で確認できます。カード契約は誤操作防止のため、この画面では変更できません。

### 銀行振込の領収書

顧客から依頼を受けたら、入金台帳と銀行画面で入金を照合し、宛名、金額、振込日、発行日を確認して領収書を発行します。同じ入金に対して二重発行しないよう、発行日と送付先を入金台帳または社内記録へ残します。

## 7. 初期設定の支援

顧客から操作方法を聞かれた場合は、[クライアント向け使い方ガイド](./CLIENT_GUIDE.md)に沿って案内します。

特に次を確認します。

- Aが最高価格になっている。
- ランクがA、B、C、Dの順に安くなっている。
- 競合施設名とURLが同じ宿を指している。
- 検索結果一覧ではなく、各施設の予約ページを登録している。
- 対応している予約サイトのURLである。

## 8. 競合データ取得の運用

本番では、アプリが予約サイトへ直接アクセスせず、ApifyのActorを通して取得します。

取得対象は、許諾済みとして設定した予約サイトだけです。現在の運用上限は、1施設・1予約サイトにつき1日2回です。

顧客のブラウザーやログイン状態には依存しません。Cloud Schedulerが午前9時と午後6時にCloud Run Jobを起動するため、顧客がログアウトしていても、パソコンの電源を切っていても取得します。

### 毎日の確認

1. Cloud Schedulerの実行結果を確認する。
2. Cloud Run Jobが成功しているか確認する。
3. Apifyの利用量と失敗したActorを確認する。
4. レベナビのカレンダーで、取得済み日数が増えているか確認する。
5. 同じ価格が不自然に連続していないか、数施設を目視確認する。

### 「未取得」が多い場合

1. Apifyの利用上限に達していないか確認する。
2. 定期実行が停止中になっていないか確認する。
3. Actorの最終実行が成功しているか確認する。
4. 予約サイトのページ構成が変わっていないか確認する。
5. 登録URLが有効か確認する。
6. 取得結果の項目名がレベナビの想定と一致しているか確認する。

原因が直るまで、疑似データを本番へ入れてはいけません。保存済みデータと「未取得」をそのまま表示します。

## 9. 表示データの意味

- 最安値：その宿泊日に予約サイト上で確認できた最も安い販売価格。
- 部屋なし：予約サイトで販売可能な部屋を確認できなかった状態。
- 残りわずか：予約サイトに残室数または残りわずかの表示があった状態。
- 未取得：取得処理がまだ行われていない、または失敗した状態。
- 前日比：同じ宿泊日の価格を、1日前の取得値と比較。
- 先週比：同じ宿泊日の価格を、7日前の取得値と比較。
- 先月比：同じ宿泊日の価格を、30日前の取得値と比較。

「部屋なし日率」は予約サイト上の掲載状態であり、その宿の実際の稼働率ではありません。問い合わせ時に誤って「満室率」と説明しないでください。

## 10. 参考ランクの説明

現在の参考ランクは、外部の生成AIが自由に価格を決めるものではありません。

1. 部屋のある競合施設の最安値を集める。
2. 平均の参考価格を計算する。
3. 顧客が登録した販売ランクのうち、その価格に近いものを選ぶ。
4. 顧客が設定した価格範囲を超えないようにする。

画面には算出理由を表示します。参考ランクは判断材料であり、販売価格を自動変更しません。

## 11. メール通知

通知先は、顧客が最初に登録し、確認を完了したログインメールです。

メール通知を実際に送るには、次の両方が必要です。

- Resendの有効なAPIキー
- Resendで認証済みの送信ドメインと送信元アドレス

設定画面に「実送信にはメール配信サービスの接続が必要です」と表示される間は、画面内通知だけが動作します。

認証メールの日本語テンプレートは [Supabase認証メールテンプレート](./supabase-email-templates.md)を使用します。Supabaseの仕様変更により、新しい無料プロジェクトで標準メール配信を使う場合はテンプレートを変更できないことがあります。その場合は独自のメール送信設定が必要です。

## 12. パスワード再設定の問い合わせ

1. 顧客にログイン画面を開いてもらう。
2. 「パスワード」を選んでもらう。
3. 登録メールアドレスを入力してもらう。
4. 「パスワードを忘れた場合」を押してもらう。
5. 迷惑メールも確認してもらう。
6. メール内のボタンから8文字以上の新しいパスワードを登録してもらう。

短時間に何度もメールを要求すると、安全対策による待ち時間が発生します。画面に表示された秒数だけ待ってもらいます。

## 13. 日次・週次・月次の確認

### 毎日

- 公開画面が開く。
- `/health` が正常を返す。
- 定期取得が成功している。
- Apifyの失敗が急増していない。
- StripeのWebhook失敗がない。

### 毎週

- 顧客ごとの取得率を確認する。
- 競合URLの無効化がないか確認する。
- Cloud RunとApifyの費用を確認する。
- 問い合わせ内容を記録し、説明文の改善に反映する。

### 毎月

- 銀行振込顧客の入金と契約期限を確認する。
- Stripeの契約数とSupabaseの利用中件数を照合する。
- Supabaseのセキュリティ診断と性能診断を確認する。
- 秘密鍵の不要な共有や退職者権限がないか確認する。
- バックアップから戻す手順を確認する。

## 14. 障害時の優先順位

1. 顧客データの漏えいを防ぐ。
2. 誤った価格を正しい価格として表示しない。
3. 二重決済や誤った契約停止を防ぐ。
4. 保存済みデータを表示できる状態を保つ。
5. 原因と影響範囲を記録する。

データ取得に失敗した場合は「未取得」と表示し、推測価格で埋めません。

## 15. 問い合わせ時に聞く内容

- 登録メールアドレス
- 施設名
- 問題が起きた日時
- 押したボタン
- 画面に表示された文章
- 画面全体の画像
- 使用した端末（パソコンまたはスマートフォン）
- 使用したブラウザー（Chrome、Edge、Safariなど）

パスワード、カード番号、秘密鍵は聞かないでください。

## 16. 現在の未完了項目

本番営業前に優先して完了する項目は次のとおりです。

1. Apifyの利用枠を確保し、90日取得と日次取得を本番で連続成功させる。
2. 楽天トラベル・じゃらんActorの取得内容を実ページと照合する。
3. Resendの送信ドメインを認証し、通知メールを実送信する。
4. Supabaseの認証メールを日本語テンプレートへ変更する。
5. 漏えい済みパスワード拒否機能を有効にする。
6. 事業者情報と問い合わせ先を環境設定へ登録する。
7. 独自ドメインを設定する。
8. 実在するパイロット施設で、登録から30日間の継続取得を確認する。
